# App Store 功能拆分章程

> 最后修改时间：2026-10-19 13:55 CST
> 文档版本：v1
> 修改说明：定义设置功能拆分的职责、接口、实施顺序和验收标准。

## 目标与范围

`apps/desktop/electron/application/app-store.ts` 同时承担应用组装、设置操作、启动恢复、会话事件和窗口投影。本轮将设置功能迁出，保留现有公开 API 和操作顺序。成功标准是业务实现只有一个归属，主类通过明确的能力接口委托，设置结果、错误处理和持久化行为保持一致。

本章程随本次用户要求直接执行。范围包括现有调用者、相关架构说明和回归验证；不更换状态库、不调整 IPC、不改变 Pi 数据格式，也不增加旧版本兼容。

## 功能归属

| 模块                                                                 | 本轮职责                                                                                 | 状态与依赖                                                                                |
| -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `application/app-store.ts`                                           | 初始化、公开入口委托、事件队列、快照发布、持久化协调                                     | 独占聚合状态、driver、catalog、session/runtime map                                        |
| `settings/preferences-owner.ts`                                      | 侧栏、分组、通知、终端 shell、透明度、语言、主题偏好                                     | 只读取偏好快照，通过限定字段的 patch 更新偏好；语言重命名默认工作区由组合点执行           |
| `settings/runtime-settings-owner.ts`                                 | 模型作用域与默认值、Provider、Skills、扩展开关、MCP、code mode、运行时重载和有效模型设置 | 接收 runtime supervisor、只读设置视图及明确的缓存、会话重载、持久化能力；不接收整个 store |
| `settings/model-settings.ts`                                         | 模型设置文件路径、读取、合并、比较和应用                                                 | 无应用可变状态；沿用当前 Pi 设置语义                                                      |
| 现有 workspace / conversation / orchestration / scheduled-task owner | 保持各自生命周期与执行职责                                                               | 不引入新的反向依赖                                                                        |

本轮保留主类中的会话事件、窗口投影、启动恢复和文件变化协调。这些路径共享选择 epoch、事件顺序和发布 revision，后续拆分须先定义各自状态归属，不能按行数切片或使用继承、混入隐藏依赖。

## 接口规则

- 新 owner 不导入 `DesktopAppStore`，不接收整个应用对象，不使用类型断言绕过 private。
- 可写接口按职责限定字段；读取视图不提供聚合状态的写权限。runtime 缓存使用按工作区读取、写入的操作，不外传可变 Map。
- 主类保留公开方法签名，现有 IPC 和 owner 调用者无需迁移。已迁出的实现从主类删除，不保留备用路径。
- 初始化、校验、写盘、刷新、广播的先后顺序保持原样。持久化失败时的内置扩展开关回滚、部分会话重载失败提示必须保留。
- 保留 `t()`、语言校验、系统语言回退和默认工作区翻译，不新增界面文案或翻译键。
- 不更改 renderer / preload / main 边界，不复制或重写 Pi runtime 行为。

## 实施顺序

1. 记录现有职责与调用者，确认设置代码使用的内部能力。
2. 提取模型设置函数，再迁出偏好和运行时设置实现；组合点接入窄接口。
3. 检查所有调用和 import，移除主类中的旧实现与无用依赖，同步架构文档。
4. 执行静态检查与现有回归用例，检查差异中的重复路径、过度抽象及转义问题。

## 验收与失败场景

| 用户流程或约束                       | 可观察结果                                          | 验证方式                                                                                         |
| ------------------------------------ | --------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 偏好、主题、语言切换及重启           | 选择立即生效，重启保留；语言切换保留草稿并同步窗口  | 现有 `settings-general`、`settings-appearance`、`settings-language` Electron 用例                |
| 模型作用域与默认设置                 | 全局 / 仓库作用域及 worktree 归属保持原语义         | 现有 `model-scope-toggle` Electron 用例                                                          |
| Provider、Skills、MCP 配置           | 现有配置流程和会话重载可用                          | 现有 `provider-settings`、`skills-settings`、`mcp-settings` Electron 用例                        |
| 未知工作区、非法偏好、写盘或重载失败 | 校验、错误传播、内置开关回滚、部分失败提示保持      | 静态审查及现有桌面 unit 回归                                                                     |
| 模块边界及调用完整性                 | 无整个 store 逃生接口，无重复业务实现，类型检查通过 | `pnpm format:check`、`pnpm lint`、`pnpm check:architecture`、`pnpm typecheck`、state-owner guard |

验证复用现有用例，不新增仅对应代码搬迁的测试。Windows Electron 使用本轮 records 下的隔离构建、profile、临时目录和输出，遵循隔离验证指南；不覆盖正式 out 或安装。fixture-backed 设置验证不代表真实 Provider 请求、原生系统交互或安装包验证。未完成项须在运行分析和交付说明中列明。
