# 应用国际化

> 最后修改时间：2026-10-18 21:59 CST
> 文档版本：v1
> 修改说明：说明语言选择、翻译资源、动态文案与验证要求。

## 语言选择

打开“设置 > 通用 > 偏好设置 > 语言”，可选择跟随系统、简体中文或 English。首次启动默认跟随系统；主进程读取操作系统的首选语言，中文变体使用简体中文，其他语言回退英语。选择立即同步到各窗口，并在重启后保留。“跟随系统”在下次启动时重新读取系统语言。

界面切换保留输入草稿、当前会话和已打开的工具。用户消息、会话标题、模型回复、代码、路径、工具原始输出、扩展作者提供的内容和许可证原文保持原样。应用负责翻译扩展的宿主界面，不改写独立扩展内部的页面。

## 资源与调用

桌面应用使用 i18next 和 react-i18next。`apps/desktop/i18n/index.ts` 为各进程创建独立实例，翻译资源随应用离线打包，不通过网络下载。英语源消息同时作为回退资源，中文译文位于 `apps/desktop/i18n/zh-CN.json`。资源关闭 key 和 namespace 分隔符，文案中的句号、冒号按普通字符处理。

新增静态文案时调用 `t("English source message")`，并添加对应中文译文。动态文案使用完整句子和具名插值，不拼接零散句段；数字和日期按当前语言格式化。需要英语单复数时，把数量和英语后缀作为独立插值传入，中文可省略后缀。

React 组件通过 `useLocale()` 订阅语言变化，相关 memo 的依赖包含当前语言。不得通过替换 DOM 文本或按语言重新挂载整棵应用树实现翻译。模块级导航项、选项等静态数据通过 getter 延迟翻译，避免导入时固化语言。

应用生成的时间线状态使用 `contracts/language.ts` 中的 `message` 描述符，由 renderer 调用 `translateMessage`。描述符保存源消息和参数，既能在现有行上切换语言，也不会改写参数中的用户文本。外部消息保持普通字符串，不附加描述符。技术标识符、IPC 名称、状态值和路径必须保持稳定，不得翻译后再用于判断或索引。

语言偏好只经受校验的 main-frame IPC 修改，主进程负责持久化和广播；renderer 不读取系统文件，也不直接导入 Electron。偏好校验与当前格式的数据损坏保护保持一致，不为旧版本数据添加迁移。

## 验证

`tests/unit/i18n.spec.ts` 检查首选系统语言回退、非法偏好、插值与外部文本保护、定时任务格式、字面量翻译目录覆盖及插值参数。`tests/unit/scheduled-task-schedule.spec.ts` 保留定时任务原有时间语义验证。

`tests/core/settings-language.spec.ts` 在可见 Electron 中检查默认语言、中英文切换、草稿保留、原生菜单、多窗口同步和重启持久化。测试使用独立会话 fixture，不请求模型，不能作为真实 provider 对话执行的证明。临时构建和运行产物按[隔离桌面验证指南](isolated-desktop-verification.md)存入本次 `records/` 目录。

新增或改动文案后运行格式、Lint、类型、架构检查及受影响的验证。静态目录覆盖检查不能证明译文质量，交付前仍需检查真实截图中的断句、溢出和混杂语言。
