# Renderer 应用入口拆分

> 最后修改时间：2026-10-19 13:40 CST
> 文档版本：v1
> 修改说明：记录 App 的组件组装、展示逻辑与状态生命周期边界。

`apps/desktop/src/app/App.tsx` 负责读取桌面状态、确定当前工作区和会话，连接对话控制器、全局命令及页面布局。所有模块仍通过现有 `window.piApp` 接口访问主进程。

## 模块职责

以下文件均位于 `apps/desktop/src/app/`。

| 文件                               | 职责                                                                                           |
| ---------------------------------- | ---------------------------------------------------------------------------------------------- |
| `use-app-appearance.ts`            | 订阅主题变化，应用主题和透明效果，生成扩展视图主题。                                           |
| `use-app-navigation.ts`            | 管理设置、技能和扩展页面的工作区选择及导航。                                                   |
| `use-app-thread-switcher.ts`       | 维护线程切换顺序，通过最新引用读取线程列表并分发选择操作。                                     |
| `use-conversation-presentation.ts` | 匹配当前会话记录，协调固定卡片、定时任务来源、加载状态、轮次变更、时间线视口、搜索及版本提示。 |
| `new-thread-surface.tsx`           | 将现有新建线程控制器连接到界面，并显示无工作区时的空状态。                                     |
| `app-workbench.tsx`                | 根据当前工具选择组装扩展、变更、文件或终端面板。                                               |

## 状态与挂载

四个应用 Hooks 均由 `App` 无条件调用，包括加载中和次级页面。页面切换不会卸载这些 Hooks，也不会因此重置线程切换顺序、搜索状态或已关闭的版本提示。草稿同步、输入控制和会话树等原有 Hooks 继续由 `App` 调用。

`NewThreadSurface` 和 `AppWorkbench` 负责组件组装，不新增业务状态或 DOM 容器。原有会话组件的 key、条件分支、事件处理与文案保留。工作台继续使用 `lazy-surfaces.ts` 中的懒加载组件和原有 Suspense 边界；设置、技能和扩展页面的懒加载仍留在 `App`。

本次拆分不涉及主进程 Store、IPC 合约或持久化格式。总体进程边界见 [架构文档](../architecture.md)。
